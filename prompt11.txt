## COLLECTIONS — v77 BUG FIXES

### `applyYearRange` — replace, not add

`game/src/hooks/setup/useScopeSelection.js`:

```js
// BEFORE (add-only)
const applyYearRange = useCallback((yearsToSelect) => {
  setSelectedYears((prev) => {
    const next = new Set(prev);
    for (const y of yearsToSelect) next.add(y);
    return next;
  });
}, [setSelectedYears]);

// AFTER (replace)
const applyYearRange = useCallback((yearsToSelect) => {
  setSelectedYears(new Set(yearsToSelect));
}, [setSelectedYears]);
```

Without this, `YearRangeModal` "Apply" appears to do nothing when the picked
range is a subset of the current selection. `handleScopeChange`'s diff logic in
`EditorScope` is correct — it just never received a "smaller" `next` set.

### `usePlayCollection.launch` — parse years

```js
import { parseYears } from '@/components/domain/Templates/templateYears';

const payload = {
  ...,
  years: parseYears(game.years),   // was: game.years?.values || []
```

### `seedSettingsFromRound` — the fix that made the modal reflect the picked level

```js
function seedSettingsFromRound(round) {
  if (!round) return;
  settings.applySettings({
    questionTypes:   round.questionTypes   ?? settings.questionTypes,
    answerMode:      round.answerMode      ?? 'choose',
    reversedAnswers: round.reversedAnswers ?? 'no',
    timer:           round.timer           ?? null,
    audioRendition:  round.reversedAudio ? 'reverse' : 'forward',
    instruments:     round.instruments     ?? 'none',
    roundCount:      round.rounds          ?? settings.roundCount,
  });
}
```

Called in three places: `handleOpenTemplate` (single-level), `handleOpenTemplate`
(multi-level placeholder before picker), and `handlePickLevel` (the real
reseed). Without the third call, Level 2 modal inherited Level 1's timer /
instruments.

## ⚠️ ACTIVE CRISIS — D1 FREE TIER EXHAUSTED

**Status:** the music-game D1 database is currently BLOCKED by Cloudflare's
free-tier daily row-read limit. All queries error with:

> "Your account has exceeded D1's free tier daily row read limit. Upgrade to a
> paid plan or wait until tomorrow (midnight UTC) to continue."

**Symptom start:** while running `SELECT * FROM collections`. That query is NOT
the culprit — it was just the trigger. The daily total was already exhausted.

**Root cause (high confidence):** `ORDER BY RANDOM()` on tables that grew during
recent admin uploads. Every round-fetch call (streaks, Sporcle) scans the whole
`tracks` table (and sometimes `instruments`) to sort them.

Cost model:

| Table size | Rows per `RANDOM()` | × 50 calls/session |
|---|---|---|
| 500 | 500 | 25,000 |
| 4,000 | 4,000 | 200,000 |
| 20,000 | 20,000 | **1,000,000** |

Combined with upload-flow writes (per-song inserts, artist-count recomputes) and
`json_each` scans in `pickArtists` for every new challenge, the daily 5M budget
was consumed.
