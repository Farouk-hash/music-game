## D1 Schema

```sql
CREATE TABLE genres (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  display_name TEXT NOT NULL,
  image TEXT,
  is_customized INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE artists (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  genre_ids TEXT NOT NULL DEFAULT '[]',   -- JSON array of ints
  image TEXT,
  tracks_count INTEGER NOT NULL DEFAULT 0,
  is_customized INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE tracks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  artist_id INTEGER,
  r2_key TEXT,                -- forward rendition (nullable)
  r2_reversed_key TEXT,       -- reversed rendition (nullable)
  position TEXT,              -- start | middle | end | custom
  label TEXT
);
CREATE UNIQUE INDEX idx_tracks_unique_clip ON tracks(artist_id, name, position);
```

**Key semantics:**
- One `tracks` row = one **slot** = `(artist_id, name, position)`.
- Both forward (`r2_key`) and reversed (`r2_reversed_key`) renditions live on the **same row**.
- Either key may be NULL. Both may be set.
- `artists.tracks_count` is a stored count of slots per artist. Recomputed on demand.

### Worker endpoints used by the game

**`GET /game/catalog`** — the only endpoint the game uses today.

Returns:
```json
{
  "genres":  [{ "id", "name", "display_name", "image" }],
  "artists": [{ "id", "name", "genre_ids", "image", "tracks_count" }],
  "counts":  { "genres", "artists", "slots", "clips" },
  "version": "ISO-date"
}
```

- `artists` is filtered to `tracks_count > 0`.
- Response has `Cache-Control: public, max-age=...`.
- Client cache-busts via a session token appended to every URL (in `lib/api.js`).

- **Eyebrows:** uppercase, `tracking-[0.2em]`, `text-highlight`, `text-xs`.

## The Game's Intent (design brief)

A single-player "name that track" quiz, no accounts, no teams.

- Player picks genres and (optionally) artists on Setup
- Play proceeds in rounds of N clips
- Question types planned (pick after confirming Setup):
  - **Name the track** — hear clip, type the title
  - **Name the artist** — hear clip, name the singer
  - **Odd one out** — play N clips, find the one not by the target artist
- Difficulty axes available from data (no schema changes needed):
  - Clip length (20s / 10s / 3–5s)
  - Position (start / middle / end / custom)
  - Rendition (forward / reversed)
  - Answer options (multiple choice vs free text)
- Score is a number in React state for v1. High score persists in localStorage.
- The `/play` route is next.

## Immediate Task

Build the **play loop**. Two paths to consider:

**A. Server-side round generation.** Add `GET /game/round?genre=&artist=&difficulty=&count=` to the Worker, returning a ready-to-render round object:

```json
{
  "question": { "type": "name-track", "prompt": "..." },
  "clips": [{ "id", "r2_key", "name", "artist_id", "position", ... }],
  "options": [...],
  "correct": "..."
}
```

**B. Client-side round generation.** `Setup` passes filters to `/play` (via URL search params), `Play` fetches the catalog (already cached) and builds rounds client-side.

**Recommendation:** Start with **B** for the first question type (`name-track`), because:
- `useCatalog` already has genres + artists cached
- No Worker changes needed for the first cut
- Fast iteration on game feel

Then migrate to **A** when you add question types that need cross-artist data (odd-one-out) or when the client can't reasonably build a round.

**First concrete step for `/play`:**

1. Pass filter state from `Setup` to `Play` via URL search (`/play?genres=1,2&artists=5,7` — empty means "all")
2. In `Play`, read the params, filter the catalog, pick N random artists with clips
3. For each artist, fetch their clips (needs a **new Worker endpoint**: `GET /game/clips?artist_id=&count=` since `/game/catalog` doesn't include clips)
4. Play the first clip with a `<audio>` element (URL: `{worker}/clips/serve?key={r2_key}`)
5. Show a text input for the track name, compare with normalization
6. Score + advance

**That step 3 endpoint doesn't exist yet.** The first new thing to build is `GET /game/clips` on the Worker — returns clips for a set of artists, with `r2_key`, `name`, `artist_id`, `position`.
