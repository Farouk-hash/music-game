## D1 Parameter Limit — CRITICAL

**Cloudflare D1 hard-caps bound parameters at 100 per SQL statement.** Exceeding it returns `D1_ERROR: too many SQL variables at offset N: SQLITE_ERROR`. This is a platform limit, not a bug in the code.

**Any query that binds a variable-length array (`scopeArtistIds`, etc.) must chunk to ≤90 elements per query.** Shared helper:

`music-game-wrangler/src/utilities/chunkedIn.js`:
```js
export const D1_CHUNK_SIZE = 90;
export async function chunkedIn(items, chunkSize, fn) {
  if (!items.length) return [];
  const size = chunkSize > 0 ? chunkSize : D1_CHUNK_SIZE;
  const out = [];
  for (let i = 0; i < items.length; i += size) {
    const chunk = items.slice(i, i + size);
    const rows = await fn(chunk);
    for (const r of rows) out.push(r);
  }
  return out;
}
```

## Sudden Death Tiebreaker — NEW v28, WORKING

**Purpose:** when a multiplayer game ends in a tie, offer a 5-question sudden-death round with forced text input and pass-and-play.

**Trigger:** `Leaderboard.jsx` shows a "⚔️ Sudden Death — 5 questions" button when scores are tied (top score > 0). Otherwise, button hidden.

**Rules:**
| Aspect | Value |
|---|---|
| Questions per batch | 5 (hardcoded `QUESTIONS_PER_BATCH`) |
| Server calls | ONE per batch |
| Scoring | Accumulate across all questions in the batch; start from 0 |
| Base score | 0 — main game's tied score is discarded |
| All players answer | Yes, all 5 questions, no elimination |
| Still tied after 5 | Another batch of 5 — loop |
| Answer mode | Forced text input, no options rendered |
| Answer check | `isCorrectForQuestion(question, typed)` — Arabic/English normalization |
| Eye icon | **Toggle only** — masks/unmasks the current typing. Commit is a separate button. |
| Pass-and-play | After each answer: handoff card → next player |
| **Early termination** | **Yes** — as soon as `leader.score - second.score > questionsLeft`, phase → `'finished'` |
| **Progress bar privacy** | **Answered segments show neutral tier until the batch reveals.** The next player must not learn the previous player's result. |

### Hook API — `useSuddenDeath({ playerIds, apiParams })`

**Returns:**
- **State:** `phase` (`loading | answering | handoff | reveal | batch-done | finished | error`), `error`, `questions`, `currentQuestion`, `currentPlayerId`, `playerIndex`, `playerCount`, `qIndex`, `batchIndex`, `scores`, `answers`, `currentQuestionAnswers`, `lastCommitted`, `draft`, `setDraft`

- **Exported helper:** `isCorrectForQuestion(question, typed)` — handles `name-position` EN↔AR canonicalization

### Progress bar privacy rule

`SuddenDeathProgress` shows `tier: 'correct' | 'wrong' | 'neutral'`. **During answering/handoff, answered segments must show `'neutral'`**, not green/red. Only when `phase === 'reveal'` (or later) should the actual correctness be exposed.

`SuddenDeath.jsx` computes `perQuestion[qIndex][playerId] = 'correct' | 'wrong' | 'answered' | null`:
- `null` — not answered
- `'answered'` — answered but result must stay hidden
- `'correct' | 'wrong'` — publicly revealed

### Early-termination math

`leaderIsUncatchable(snapshot, questionsLeft)`:
```js
leader.score - second.score > questionsLeft
```
Runs inside `commitAnswer` after the last player answers, and again in `nextQuestion`. If true, `phase = 'finished'` immediately.
