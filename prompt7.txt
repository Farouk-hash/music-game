## PROFILE SYSTEM — COMPLETE

### Identity model

- **Anonymous profile id.** Server-generated UUID. No auth.
- **Cross-device** via an 8-char alphanumeric recovery code (uppercase, no `O/0/I/1`). Generated once at profile creation, returned only to the creating client.
- **The UUID is the sole credential.** Stored in `localStorage['music-game:profile:id']`.
- **Silent creation.** `useProfile` creates a profile on first mount with a placeholder nickname (`Player-XXX`).
- **Restore deletes the old profile.** When a client restores from a recovery code, the old profile row + its R2 avatar are **deleted** (best-effort, fire-and-forget). See "Recovery / Restore" below.

### `DELETE /profiles/:id` semantics (v53)

```js
export async function deleteProfile(request, env, { id }) {
  if (!id) return error('id required', 400);

  const row = await env.DB.prepare(
    'SELECT avatar_r2_key FROM profiles WHERE id = ?'
  ).bind(id).first();

  // Idempotent: deleting a missing profile is a no-op success.
  if (!row) return json({ ok: true, deleted: false });

  await env.DB.batch([
    env.DB.prepare('DELETE FROM profile_favorites WHERE profile_id = ?').bind(id),
    env.DB.prepare('DELETE FROM profiles WHERE id = ?').bind(id),
  ]);

  if (row.avatar_r2_key) {
    try { await env.AUDIO.delete(row.avatar_r2_key); } catch {}
  }

  return json({ ok: true, deleted: true });
}
```

**No auth.** Consistent with the rest of the profile API — the UUID is the credential.

### `PUT /profiles/:id` — bulk save semantics

- **All sections optional.** Sending `{ nickname }` alone updates the nickname; favourites untouched.
- **If `favorites` is present, the whole set is replaced** — `DELETE FROM profile_favorites WHERE profile_id = ?` then `INSERT` each. Runs in a single `env.DB.batch()`.
- **If `avatar` is present**, sets `avatar_kind` and (only when `kind === 'generated'`) `avatar_style` + `avatar_seed`. **Does NOT touch `avatar_r2_key`** — the avatar upload path owns that.

### Recovery / Restore (v53)

`useProfile.js`'s `recoverProfile(code)`:

1. Read the **old id** from localStorage.
2. `POST /profiles/recover { recoveryCode }` → `{ id: newId }`.
3. Replace localStorage id → `newId`. Clear recovery code + recovery hidden flag. Clear cached profile. Invalidate `['profile']`.
4. **Best-effort delete:** if `oldId && oldId !== newId`, fire `DELETE /profiles/<oldId>`. Errors are swallowed with a `console.warn`.

**The delete is intentionally post-switch, fire-and-forget** — if it fails, the restore has already succeeded and the old row simply lingers (harmless).

### Leave behaviour (mode-agnostic)

- **Lobby:** `DELETE FROM players WHERE id = ?`. If empty → `deleteAll()`. If host left and someone else present → `#promoteNextHost()`.
- **In-game:** `UPDATE players SET left = 1 WHERE id = ?`. If host left → demote + `#promoteNextHost()`.

### `#promoteNextHost`

Clears all stale `is_host` flags, then promotes the earliest-joined `left = 0` player by `rowid ASC`.

### `#rejoin`

- No-op if not left.
- Checks `answers` table for current question → sets `locked` accordingly.
- Clears stale `is_host` flag if another active host exists.

### `#answer`

- Guards against duplicate answers via an `answers` table lookup, even if `locked` is stale.
- Speed mode: first correct answer ends the question.
- Collect mode: ends when all active players have answered.


**`useRoomProfiles`** uses `useQueries` keyed by `['profile', id]` — **same key as `useProfile`**, so the local player's profile is already cached and no extra request is made. Unwraps `{ profile }` via `select: (data) => data?.profile ?? null`.

**`PlayerAvatar`** resolution order:

1. `avatar.avatar.kind === 'uploaded'` → `absoluteAvatarUrl(profile)` (from `profileApi.js`)
2. `avatar.avatar.kind === 'generated' && avatar.avatar.style` → `getAvatarUrl(seed, { style })` using the profile's own style + seed
3. fallback → DiceBear with `DEFAULT_AVATAR_STYLE` (`adventurer-neutral`) + the player name as seed

**`absoluteAvatarUrl(profile)`** lives in `profileApi.js`:
```js
export function absoluteAvatarUrl(profile) {
  if (profile?.avatar?.kind !== 'uploaded') return null;
  return `${BASE}/profiles/${profile.id}/avatar`;
}
```

**`BASE`** in `profileApi.js` = `VITE_API_BASE0` with `/game` suffix stripped (idempotent).

**⚠️ GOTCHA (documented because it cost us hours):** the avatar threading requires `profilesById` to reach `RoomPanel` **in the live `<RoomPanel>` render inside `<Modal>` in `SporcleModal.jsx`**. There was a duplicated dead-code `<RoomPanel>` block above the `return` that looked like it applied the prop but didn't. If avatars fall back, check that the **live** `<RoomPanel>` inside the `<Modal>` has `profilesById={profilesById}`.

## Sporcle Client — Key Design Decisions

**Long-poll driven.** `useHostSporcle` loops `GET /state?since=N`. DO holds ~3s when version unchanged. **Breaks on 404** (terminal) instead of retrying.

**Overlays driven by server timestamps.** `CountdownOverlay` takes `endsAt`, recomputes every 100ms.

**`refresh()` aborts in-flight polls** after any action.

**State hoisting — single polling loop.** `SporcleModal` does NOT poll. Play owns the loop and passes `state`, `actions`, `myId`, `profilesById` down.

**Mid-game rejoin — the `isLocked` guard.** Play computes `isLocked = !!me?.locked`. `handlePick` refuses when `isLocked`. DO's `#rejoin` conditionally resets `locked`; `#answer` checks the `answers` table.

**Auto-rejoin on refresh.** Ref-guarded effect calls `actions.rejoin(myId)` if the local player is `left: true`.

**Leave beacon on tab close.** `beforeunload` → `sendBeacon`. Unreliable on mobile.

**`response.js` bare-number status.** `json(data, 404)` works. Also `sporcleApi.request` throws on `{ ok: false }` even with 2xx.
