### Identity model

- **Anonymous profile id.** Server-generated UUID. No auth.
- **Cross-device** via a **recovery code** — 8-char alphanumeric (uppercase, no `O/0/I/1`). Generated once at profile creation. Returned only to the creating client.
- **The UUID is the sole credential.** Stored in `localStorage['music-game:profile:id']`.
- **Silent creation.** `useProfile` creates a profile on first mount with a placeholder nickname (`Player-XXX`). The recovery code is stored in `localStorage['music-game:profile:recoveryCode']` and shown once in the modal until dismissed.

### `PUT /profiles/:id` — bulk save semantics

- **All sections optional.** Sending `{ nickname }` alone updates the nickname; favourites untouched.
- **If `favorites` is present, the whole set is replaced** — `DELETE FROM profile_favorites WHERE profile_id = ?` then `INSERT` each. Runs in a single `env.DB.batch()` (transactional).
- **If `avatar` is present**, sets `avatar_kind` and (only when `kind === 'generated'`) `avatar_style` + `avatar_seed`. **Does NOT touch `avatar_r2_key`** — the avatar upload path owns that.

**Known limitation:** if `avatar.kind === 'generated'` is sent while a valid `avatar_r2_key` exists, the profile still has a stale R2 key. **UI-side fix:** `ProfileModal.handleSave` only sends the `avatar` block when `usingUploaded === false`, so the R2 key isn't clobbered. The stale key is harmless but should be removed via `DELETE /profiles/:id/avatar` if the user wants to free storage.

|---|---|---|

### Leave behaviour

- **Lobby:** `DELETE FROM players WHERE id = ?`. If empty → `deleteAll()`. If the host left and someone else is present → `#promoteNextHost()`.
- **In-game:** `UPDATE players SET left = 1 WHERE id = ?` (**not `locked`** — that broke rejoin-mid-question and was fixed). If host left → demote + `#promoteNextHost()`.

### `#rejoin`

- No-op if not left.
- Checks for an existing answer row for the current question → sets `locked` accordingly (0 if unanswered, 1 if answered).
- Clears stale `is_host` flag if another active host exists.

### `#answer`

- Guards against duplicate answers via an `answers` table lookup, even if `locked` is stale.
- In speed mode, first correct answer ends the question.
- In collect mode, ends when all active players have answered.

### `#promoteNextHost`

Clears all stale `is_host` flags, then promotes the earliest-joined `left = 0` player by `rowid ASC`.

### `getState` null-guards

Both `fresh` (after the 3s long-poll hold) and `latest` (before `#buildState`) are null-guarded — the room may be destroyed mid-hold.

## Sporcle Client — Flow

**Host:** `/setup` → pick scope → click **Sporcle** → modal at `'host'` → fill name + settings → **Create room** → POST `/create` → localStorage → `navigate('/sporcle/play/<CODE>')` → Play mounts, polls → `phase='lobby'` → modal at `'room'` → `RoomPanel` shows code + roster + Start.

**Guest:** same via Join tab.

**Shared link:** `/sporcle/play/<CODE>` directly → modal at `'join'` with code prefilled.

**Game start:** Start → DO sets `loading` → modal stays open → `RoomPanel` renders `<LoadingOverlay inline />` → DO flips to `countdown` → `<CountdownOverlay inline />` → DO flips to `question` → Play's effect → `modalOpen=false` → Q1.

**Game end:** `phase='finished'` → Play navigates to `/sporcle/result/<CODE>`.

## Sporcle Client — Key Design Decisions

**Long-poll driven.** `useHostSporcle` loops `GET /state?since=N`. DO holds ~3s when version unchanged. **Breaks on 404** (terminal) instead of retrying.

**Overlays driven by server timestamps.** `CountdownOverlay` takes `endsAt`, recomputes every 100ms.

**`refresh()` aborts in-flight polls** after any action.

**State hoisting — single polling loop.** `SporcleModal` does NOT poll. Play owns the loop and passes `state`, `actions`, `myId` down.

**Mid-game rejoin — the `isLocked` guard.** Play computes `isLocked = !!me?.locked`. `handlePick` refuses when `isLocked`. DO's `#rejoin` conditionally resets `locked`; `#answer` checks the `answers` table.

**Auto-rejoin on refresh.** Ref-guarded effect calls `actions.rejoin(myId)` if the local player is `left: true`.

**Leave beacon on tab close.** `beforeunload` → `sendBeacon`. Unreliable on mobile.

**`response.js` bare-number status.** `json(data, 404)` works. Also `sporcleApi.request` throws on `{ ok: false }` even with 2xx.

**Two places avatars are used:**

## Known Open / Broken

### 1. **Sporcle nickname autofill not yet wired**
`SporcleModal.jsx`'s host/join name inputs and `MultiplayerModal.jsx` should prefill from `profile.nickname`. The pattern:

```jsx
const { profile } = useProfileContext();
const [hostName, setHostName] = useState('');
useEffect(() => {
  if (!profile?.nickname) return;
  setHostName((prev) => prev || profile.nickname);
}, [profile?.nickname]);
```

`prev || nickname` preserves typed input if the profile updates while the modal is open.

### 2. **Avatar system half-wired (room-scoped styles)**
The pieces exist:
- `pickRoomAvatarStyle()` in `avatarProvider.js`.
- `PlayerAvatar` supports a `style` prop.
- `PlayerRoster.jsx` and `SporcleProgress.jsx` accept an `avatarStyle` prop and render `<PlayerAvatar seed={p.name} style={avatarStyle} />` (assumed, verify).

**Not yet wired:**

**Until wired, all Sporcle players use `adventurer-neutral`.**

### 3. **Full 2-player Sporcle run on deployed not yet verified after v50+**
