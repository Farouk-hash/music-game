## SPORCLE — PLAY AGAIN WITH SETTINGS (v70 - IMPLEMENTED)

### Purpose

The host can change the game scope (mode, count, genres, artists, years) **without leaving the Result screen** — keeping them from losing their host status via `beforeunload`.

### Server-side: DO action `start_again`

```js
if (type === 'start_again') return this.#startAgain(player, room, action);
```

**`#startAgain(player, room, action)`** (host-only, from `finished`):
1. Merges `action.config` into the existing room config.
2. Resets `score = 0, ready = 0, locked = 0` for all active players.
3. Deletes all `questions` and `answers`.
4. Sets `phase = 'loading'`, resets `q_index = 0`, `tie_breaker = 0`, bumps version.
5. Calls `ctx.waitUntil(this.#loadQuestionsAndCountdown())` — same as `#start`.

### `#buildState` change

Exposes `roomConfig: config` on the state object so the client can pre-fill the modal with the current scope.

### Client-side files

```
game/src/
└── components/domain/Sporcle/
    └── ReplaySettingsModal.jsx    # NEW — host-only settings modal
```

### `ReplaySettingsModal` — features

- **Mode:** Speed / Collect.
- **Count:** 5 / 10 / 15 / 20.
- **Genres:** dense grid (3 columns on mobile, 4 on desktop via `[&_.grid]:grid-cols-3 sm:[&_.grid]:grid-cols-4`).
- **Artists:** searchable, dense grid.
- **Years:** draggable-selectable.
- Pre-populated from `state.roomConfig`.

**Layout (critical):**
- Modal container: `flex flex-col h-[85vh]` — **fixed height** (not `max-h`), so the inner body has a determinate space to scroll into.
- Header: `shrink-0` so it stays pinned at the top.
- Body: `flex-1 overflow-y-auto p-6 space-y-6` — this is the **only** scroll area.
- Footer: `shrink-0` — pinned at the bottom.
- **No nested `max-h` scroll areas** inside the sections — this caused double-scroll UX bugs.

### Wiring in `Result.jsx`

```jsx
<ReplaySettingsModal
  open={replayOpen}
  onClose={() => setReplayOpen(false)}
  initialMode={state.mode}
  initialCount={state.roomConfig?.count ?? state.totalQuestions}
  initialConfig={state.roomConfig || {}}
  onSubmit={async (config) => {
    await actions.startAgain(myId, config);
  }}
/>
```

### Flow

1. Game ends → Result screen.
2. Host clicks **Play again →** → modal opens.
3. Host edits scope/mode/count.
4. Clicks **Start game →** → DO merges config, sets `phase = 'loading'`.
5. Every client's `useHostSporcle` poll sees `phase !== 'finished'`.
6. The `useEffect` in `Result.jsx` (which watches `state.phase`) fires `navigate('/sporcle/play/<code>')`.
7. All players return to `/play` and the game starts with the new settings. **Host status preserved** — no `#leave` was fired.

### `useHostSporcleActions` addition

```js
startAgain: (playerId, config) => run('start_again', { playerId, config }),
```
