## TOAST SYSTEM — NEW (v57)

**File:** `game/src/hooks/ui/useToast.jsx` (**`.jsx` — must have the JSX extension**).

**Three exports:**
- `ToastProvider` — context provider. Mounted in `main.jsx` wrapping `<BrowserRouter>`.
- `useToast()` — returns `{ toast, show, dismiss }`.
- `ToastHost` — renders the current toast. Mounted in `App.jsx` as a sibling of `<Shell>`.

**`show(config)` config shape:**
```js
{
  message,               // string
  actionLabel,           // optional — e.g. 'Undo'
  onAction,              // called when the action button is clicked
  onDismiss,             // called when the toast expires WITHOUT the action
  durationMs,            // default 6000
}
```

**Dismiss reasons — CRITICAL:**
- `'cancel'` — user clicked the action button (Undo). Fires `onAction`, **does NOT fire `onDismiss`**.
- `'expire'` — timer ran out OR user clicked the `✕` on the toast. Fires `onDismiss`.
- Replacement by a new toast — `show()` calls `clearTimer()` + `setToast(new)` — **fires neither**.

**`ToastHost` UI:**
- Positioned top-center, `fixed top-4 inset-x-0 z-[70]`.
- Card: rounded, bordered, `bg-surface`, `flex-col` with a progress bar as the bottom sibling.
- Row: message · action label (accent) · ✕ button.
- **Progress bar** (`ToastProgressBar`): drains 100% → 0% via `requestAnimationFrame` over `durationMs`. Three-tier color: `bg-correct` (>66%), `bg-highlight` (33–66%), `bg-wrong` (<33%). 200ms `transition-colors` between tiers.

**Known limitation:** single-toast system. Showing a new toast replaces the current one and **does not fire the replaced toast's `onDismiss`**. So if a user dismisses invite A, then dismisses invite B before A's window expires, invite A's server delete never fires. Acceptable for v1.

**`InvitesTab` uses the toast:**

```js
function handleDismiss(inv) {
  setHidden((prev) => new Set(prev).add(inv.id));       // hide locally
  show({
    message: 'Invitation removed',
    actionLabel: 'Undo',
    durationMs: 30_000,
    onAction: () => { /* unhide locally — no server call */ },
    onDismiss: () => { dismiss.mutate(inv.id, { onSettled: /* unhide */ }); },
  });
}
```

**Flow:** click ✕ → row hidden → toast appears (30s, green→gold→red bar) → Undo un-hides (no server call) OR expiry fires `POST /invites/dismiss` (hard delete).

### 8. **Orphaned profiles**

`beforeunload`/`sendBeacon` unreliable on mobile Safari. Needs heartbeat + staleness sweep.

### 10. **Dead `avatarStyle` variable in `Play.jsx`**
`const avatarStyle = state?.avatarStyle ?? undefined;` — leftover, never used.

### 11. **Toast replacement drops the pending `onDismiss`**
Single-toast system. If toast A is on screen and toast B is shown, A's `onDismiss` never fires. Known limitation — accept, or queue toasts.

### 12. **Leaderboard — spec locked in, not built**
Design shelved. Locked-in decisions: **Sporcle Hall of Fame only** (product A), **DO writes at `finished` via service binding** (W1), **one row per player per game**, **G1 score-over-time graph** (hand-rolled SVG), **guests excluded**, **Header link entry point**.

### 13. **Invite cleanup sweep**
The 2h auto-hide filter is client-visible only — rows accumulate in D1 forever. Consider a periodic `DELETE FROM room_invites WHERE created_at < datetime('now', '-7 days')`. Options: opportunistic delete in `listPendingInvites`, or a daily cron.
