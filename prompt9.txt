## SPORCLE — HEARTBEAT + LOBBY-WAIT TIMERS (v71/v72)

### The problem solved

1. Mid-game roster wasn't updating when a player left.
2. Result screen didn't reflect host leaves.
3. Mobile tab-close is unreliable → needs server-side sweep.
4. Rooms sat idle forever (host alone / nobody ready / host not starting) → wasted DO requests.

### The full design

**Players have `left` values:**

| Value | Meaning |
|---|---|
| `0` | present |
| `1` | explicit leave (button / tab-close beacon) — never auto-rejoined |
| `2` | timed out (heartbeat) — auto-rejoins on next poll / ping |

**Heartbeat = existing long-poll.** No separate heartbeat hook. Every `GET /state?since=N&playerId=X` updates X's `last_seen`. The DO sweeps stale players every 5s (SWEEP_INTERVAL_MS).

### DO schema additions

```sql
players.last_seen INTEGER NOT NULL DEFAULT 0

room.lobby_wait_started_at INTEGER
room.lobby_wait_reason     TEXT   -- 'alone' | 'no-ready' | 'host-idle' | NULL
```

Both are `ALTER TABLE`-migrated in the constructor with try/catch.

### Constants

```js
const HEARTBEAT_TIMEOUT_MS       = 30000;   // 30s → mark left=2
const LOBBY_HEARTBEAT_TIMEOUT_MS = 2*60000; // 2min in lobby (share code = slow)
const SWEEP_INTERVAL_MS          = 5000;
const ALONE_TIMEOUT_MS           = 60000;   // client — alone window
const NO_READY_TIMEOUT_MS        = 60000;   // client — nobody-ready window
const HOST_IDLE_TIMEOUT_MS       = 60000;   // client — all ready, host not starting
```

### Lobby-wait reasons (server-side, `#refreshLobbyWaitWindow`)

Called after every player-list or ready-flag change:
- `init`, `join`, `#leave`, `#rejoin`, `#ready`

Logic:
- **`'alone'`** — `activeCount === 1 && hostCount === 1`
- **`'no-ready'`** — `nonHostActive > 0 && readyNonHost === 0`
- **`'host-idle'`** — `nonHostActive > 0 && readyNonHost === nonHostActive` (all non-hosts ready, host hasn't started)
- **`null`** — all other cases

**If reason is unchanged, timer is preserved.** If reason changes, `lobby_wait_started_at` resets to `now`.

The reason + timestamp are exposed in state as:
```js
lobbyWaitStartedAt: room.lobby_wait_started_at ?? null,
lobbyWaitReason:    room.lobby_wait_reason     ?? null,
```

Host-only, destroys the room:

## MATB3AA MEDIA URL MIGRATION (v72)

### The bug

matb3aa migrated from `/media/<file>.mp3` to **`/storage/media/<file>.mp3`** when they moved to a BeMusic-powered SPA. Old URLs return `200 text/html` (SPA shell), so `download()` in `server/scripts/instrumental/batch.js` silently saved HTML to `source.mp3`. `ffprobe` failed with "Failed to find two consecutive MPEG audio frames."

### The fix

`absolutizeSrc()` in `batch.js` **normalizes any input** to `https://www.matb3aa.com/storage/media/<file>`:

```js
function absolutizeSrc(src) {
  if (!src) return null;
  const base = (MATB3AA_AUDIO_BASE || 'https://www.matb3aa.com').replace(/\/$/, '');
  if (/^https?:\/\//i.test(src)) {
    const filename = src.replace(/^https?:\/\/[^/]+\//i, '');
    const pathOnly = filename.replace(/^(storage\/)?media\//i, '');
    return `${base}/storage/media/${encodeURIComponent(decodeURIComponent(pathOnly))}`;
  }
  const filename = src.replace(/^(storage\/)?media\//i, '').replace(/^\//, '');
  return `${base}/storage/media/${encodeURIComponent(decodeURIComponent(filename))}`;
}
```

### Strict audio validation in `download()`

Now rejects non-audio BEFORE saving:
- Size `< 200_000` bytes → throw with preview
- Magic bytes not MP3 (`0xFF 0xE0..`) / ID3 / MP4 (`ftyp`) → throw with preview

Silent HTML-to-MP3 corruption is no longer possible.

### Confirmed working

```
HTTP 200, Content-Type: audio/mpeg, Content-Length: 2523993
```

Downloaded correctly through `batch.js` → demucs → segment output.

### What to remember for future pipelines

**Any new pipeline that reads matb3aa media must use `/storage/media/`.** The API's `src` field still returns `/media/` (legacy) for backward compat. `src_local: true` in the API response is a hint that matb3aa's own frontend would rewrite the URL client-side.
